## О проекте

Внутренний продукт Axis Consult. Приложение для Mac записывает встречу, локально распознаёт русскую речь и автоматически предлагает ответы по материалам встречи и контексту сделки Битрикс24. MCP предоставляет агентам доступ к выбранным встречам. OpenRouter включается отдельно для разрешённых данных.

## Текущее состояние

Реализованы запись и локальная транскрипция, каталог ASR, материалы, автоматические подсказки, структурированное резюме и чат, личный Битрикс24, календарь, MCP и подписанные обновления. Сборка0.3.5(15) установлена; добавлены компактная библиотека с папками/сортировкой и чтение Keychain вне MainActor. Полный CI15 и переносимая упаковка прошли. Фактическая приёмка и42 требования находятся в STATUS.md: качество реального резюме, живой CRM-экспорт и второй Mac пока не приняты. Личный вебхук требует явного доступа macOS. ## Общий протокол агентных сред

`AGENTS.md` является относительной ссылкой на `CLAUDE.md`. Править только `CLAUDE.md`.

В штабе перед работой прочитать инструкции родительского workspace, глобальный `~/.claude/CLAUDE.md`, активные rules и relevant_standards. Запустить штабной `project_resolve.py` с абсолютным cwd этого проекта. Для непустячных кодовых задач выполнить `vault_search.py`.

Канонические skills и роли находятся в `~/.claude/`. Использовать доступные инструменты среды; наличие settings.json не подтверждает подключение MCP. Перед командами применять `hq_check.py command`, перед записью `hq_check.py file`, перед коммитом и завершением `hq_check.py staged`. Если штабные источники недоступны в отдельном клоне, явно назвать ограничение.

После начального bootstrap работать в отдельной ветке и дереве `<repo>/.worktrees/<task>`. Не менять работу другого ведущего агента. Поля владения находятся в STATUS.md. До слияния кодовой ветки требуется независимое перекрёстное ревью.

## Проверки и запуск

Команды: `bash scripts/ci-local.sh` (контракты ядра, импорт материалов, CRM/календарь, release .app, диагностика, плавающая панель, синтетическое русское аудио), `bash scripts/build-app.sh`, `bash scripts/setup-model.sh`. Доступны whisper.cpp small/medium/turbo и Parakeet v3. Локальная генерация использует Ollama; клиентские данные не получают облачный запасной маршрут. XCTest отсутствует в установленном CLT, поэтому CoreChecks является отдельной Foundation-программой с проверками контрактов. Полный протокол: `docs/TESTING.md`.

## Данные и интеграции

1. Клиентские аудио, КП, транскрипты, модели и ключи не коммитить.
2. Битрикс24 сначала читать; поля, стадии и календарь не менять автоматически.
3. Ключи хранить в Keychain или разрешённом локальном хранилище; не выводить.
4. OpenRouter по умолчанию выключен. Конфиденциальные клиентские материалы туда не отправлять.
5. MCP не начинает запись и не изменяет CRM. Доступ к встречам пользователь включает явно.
6. Vault-статью о результатах оформить после проверки прототипа по решению пользователя.

## Папки

`_input/` и `_materials/` содержат локальные исходные материалы, `_output/` содержит результаты для владельца. Имена выдаваемых файлов: `YYYY-MM-DD_v<N>_<name>.<ext>`. `docs/` содержит проектное описание и планы. `_vault/inbox/` содержит локальные заготовки знаний. В runtime данные хранятся в Application Support, а не в репозитории.
