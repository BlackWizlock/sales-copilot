# Восстановление старой записи с эхом

`repair-echo.py` создаёт отдельную производную копию из исходных WAV и `session.json`. Утилита работает локально, не изменяет манифест, исходные фрагменты, транскрипцию и существующий `meeting.m4a`. Приложение не требуется запускать. Зависимости: уже установленный Python 3 с NumPy; для M4A нужен уже установленный ffmpeg. Автоматической установки и сетевых обращений нет.

## Запуск

Сначала получить только численные оценки. Вместо `<meeting-directory>` указать абсолютную физическую папку конкретной встречи, где находится `session.json`:

```bash
timeout 300 python3 scripts/repair-echo.py '<meeting-directory>' --analyze-only
```

Производная копия по умолчанию сохраняется рядом как `meeting.echo-reduced.m4a`:

```bash
timeout 600 python3 scripts/repair-echo.py '<meeting-directory>'
```

Можно задать другое новое имя `.m4a` через `--output`. Родительская папка должна уже существовать, принадлежать текущему пользователю и иметь права 0700. Утилита не меняет права исходной папки. Файл результата создаётся с правами 0600. Существующий файл, символическая ссылка и имя `meeting.m4a` отклоняются; перезапись не предусмотрена. Для повторного сравнения задать новое имя:

```bash
timeout 600 python3 scripts/repair-echo.py '<meeting-directory>' --output '<private-output-directory>/meeting.echo-reduced-v2.m4a'
```

При `--analyze-only` не создаются ни результат, ни временные файлы. Режим нельзя сочетать с `--output`. При кодировании временные WAV и M4A хранятся в отдельной папке 0700, файлы имеют права 0600 и удаляются после операции. Самостоятельный вызов локального ffmpeg использует фиксированные аргументы, только файловый ввод и тайм-аут 300 секунд. Содержимое его вывода не попадает в журнал.

## Что делает обработка

Исходные каналы PCM16 mono 16 кГц восстанавливаются по `start` каждого фрагмента; пропуски заполняются тишиной. Длительность WAV должна совпадать с манифестом с точностью до двух отсчётов. Повторные имена отклоняются. Парные пересечения фрагментов одного источника длительностью до одной секунды включительно усредняются по каждому отсчёту через счётчик покрытия. Шкала времени и конечная длительность не сдвигаются; результат не зависит от порядка фрагментов в манифесте. Более длинное пересечение и одновременное покрытие тремя фрагментами отклоняются. Отсутствующий WAV, включая последний фрагмент, вызывает отказ: утилита не обрезает встречу и не подменяет потерю файла тишиной.

В окнах по две секунды вычисляется нормированная корреляция микрофона с каналом встречи. Ищется положительная задержка утечки от 0 до 500 мс и один коэффициент усиления до 3 по модулю. При достаточной корреляции вычитается оценка утечки. При уверенной связи остаток микрофона дополнительно приглушается примерно на 12 дБ там, где присутствует оценка эха. При отсутствии сигнала встречи микрофон не приглушается. Затем чистый канал встречи смешивается с обработанным микрофоном. При необходимости общая громкость уменьшается до пика 0,97, чтобы избежать перегрузки.

Это ограниченное подавление утечки по известному опорному каналу, не полноценный акустический эхокомпенсатор. Нелинейный динамик, реверберация комнаты, сжатие, переменная задержка внутри окна и утечка с задержкой больше 500 мс могут оставлять слышимое эхо. Границы окон могут быть слышны. Владелец допускает агрессивную обработку: тихая одновременная речь рядом с микрофоном может потеряться. Речь микрофона без звука встречи сохраняется до общей регулировки пика и потерь AAC.

## Оценки и ограничения

Stdout содержит только JSON с длительностью, числом фрагментов, `overlap_samples` и `overlap_segments`, количеством обработанных окон, медианами задержки, коэффициента и корреляции. `estimated_mic_reduction_db` показывает уменьшение полной энергии микрофонного канала. Это не измеренная разборчивость, не качество разговора и не отдельная оценка эха при одновременной речи. В режиме записи также выводятся число отсчётов и коэффициент регулировки пика. `overlap_samples` суммирует число отсчётов парного перекрытия по обоим источникам; `overlap_segments` считает пары пересекающихся фрагментов. Названия, пути, текст встречи и ключи не выводятся. Ошибка выдаёт общее сообщение без исходного содержимого.

Предельная встреча: 2 часа, 20 000 фрагментов, 1 ГиБ исходных WAV. Манифест ограничен 8 МиБ, отдельный WAV 8 МиБ и 120 секундами. Загрузка использует два исходных массива float32 и два счётчика покрытия uint8; счётчики освобождаются до обработки. Затем расчёт удерживает два исходных и один обработанный массив float32; для двух часов потребуется примерно 1,4 ГиБ памяти плюс накладные расходы. Пути с символическими ссылками, ссылки вместо файлов, жёсткие ссылки, неподдерживаемый формат, неверные времена и повреждённые данные отклоняются. Публикация результата использует эксклюзивное создание, поэтому не заменяет существующий файл даже при гонке.

## Синтетическая проверка

```bash
timeout 180 python3 -m unittest discover -s Tests/AudioRepair -v
```

Проверяются известные задержка и усиление, снижение эха более 25 дБ для одного пути и более 15 дБ с дополнительным отражением, сохранение микрофонной речи без опорного сигнала, конечность отсчётов, длительность и размещение фрагментов, усреднение парных пересечений обоих каналов и независимость от порядка, отказ при тройном или слишком длинном пересечении и отсутствующем последнем WAV, отсутствие изменений исходников, безопасные отказы и реальный M4A через локальный ffmpeg. Эти результаты относятся к синтетическим сигналам. Качество конкретной старой встречи требует прослушивания производной копии владельцем.
