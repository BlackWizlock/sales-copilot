# Обновления с одного сервера

Приложение читает HTTPS JSON при запуске, затем раз в шесть часов и по кнопке «Проверить обновления». Проверка и скачивание выполняются независимо от записи. Совместимая новая сборка показывает «Доступна новая версия» и кнопку установки. Установка запрещена во время записи и обработки встречи, включая повторную проверку после скачивания и перед завершением приложения.

## Настройка канала

В `Contents/Info.plist` до подписи добавить `AxisUpdateFeedURL` с постоянным адресом JSON на сервере владельца. Например, `https://updates.axisconsult.ru/copilot/alpha/latest.json`. Этот официальный адрес задаётся в подписанном Info.plist. Факт работы HTTPS и публикации конкретного релиза проверяется отдельно. При самостоятельной сборке из публичного репозитория нужно задать собственный адрес сервера до подписи; чужой сертификат не сможет установить релиз официального канала. Для локальной проверки можно установить строковый параметр `axisUpdateFeedURL` через defaults для домена `ru.axisconsult.SalesCopilot`; удалить его после проверки. Сотрудникам поставляется подписанный bundle с настроенным адресом. Пустая настройка отключает автоматические сетевые проверки; ручная кнопка сообщает, что сервер ещё не настроен.

JSON и ZIP должны находиться на одном HTTPS origin. Перенаправления на другой сервер, HTTP, URL с паролем и фрагментом отклоняются. Ключи, аудио, встречи, идентификаторы пользователя и CRM в запросы не входят. Используется системная проверка TLS без исключений.

Контракт JSON версии 1:

```json
{
  "schema": 1,
  "version": "0.3.0",
  "build": "10",
  "architecture": "arm64",
  "minimumOS": "15.0",
  "url": "https://updates.axisconsult.ru/copilot/alpha/AxisCopilot-10-arm64.zip",
  "sha256": "<64 hexadecimal characters>",
  "size": 500000000
}
```

`build` сравнивается численно, по компонентам, с `CFBundleVersion`. Равная и более старая сборка не предлагается. Номер не сбрасывать при смене публичной версии. Новая сборка для неподдерживаемой macOS не предлагается. ZIP содержит единственную корневую папку AxisCopilot.app. Символические ссылки и специальные файлы не допускаются; комплект с такими файлами следует упаковать без ссылок и подписать заново до публикации.

## Подготовка релиза владельцем

1. Настроить постоянный адрес в Info.plist, выполнить шаг увеличения версии ниже, собрать и подписать приложение прежней постоянной идентичностью из Keychain. Не использовать ad-hoc, не экспортировать закрытый ключ. У сотрудников закрытого ключа нет.
2. Дождаться успешного полного локального прогона и перекрёстного ревью. Проверить живое обновление на тестовом Mac с предыдущей подписанной сборки: запись до и после, микрофон, звук встречи, сохранённая история. Сохранение разрешений TCC требует этой проверки на двух сборках; один и тот же сертификат сам по себе её не заменяет. Не вызывать tccutil reset.
3. Подготовить локальный каталог публикации:

```sh
python3 scripts/publish-update.py _output/employee-arm64/AxisCopilot.app \
  --output _output/update-channel \
  --feed-url https://updates.axisconsult.ru/copilot/alpha/latest.json
```

Для подробного запуска до этой команды выполнить `timeout 1200 bash scripts/package-employee.sh`. Публиковать нужно именно переносимый комплект сотрудника, содержащий whisper-cli, Small и модели голосов; комплект разработчика `_output/AxisCopilot.app` не подходит. Скрипт ничего не отправляет в сеть. Он проверяет наличие переносимых компонентов, подпись приложения и помощника, одинаковый сертификат, arm64, метаданные и безопасные пути. Сначала атомарно размещает неизменяемый архив, затем JSON в локальном каталоге. При изменении содержимого существующего номера сборки отказывает. Для воспроизводимой повторной публикации использовать уже подготовленный архив и JSON.

## Сервер

Один статический HTTPS каталог на сервере владельца достаточен. Нужны действующий TLS-сертификат, DNS, дисковый запас на текущую и предыдущие версии. Каталог не должен исполнять загруженные файлы. JSON отдавать с `Cache-Control: no-cache`, ZIP с `Cache-Control: public, max-age=31536000, immutable`; отключить автоматическое сжатие ZIP. Настройку сервера согласовать с его существующим владельцем и правилами инфраструктуры.

При переносе локального каталога на сервер сначала загрузить ZIP под временным именем, проверить размер и SHA-256 на сервере и атомарно переименовать. Затем загрузить JSON под временным именем и атомарно заменить latest.json. Замена должна выполняться на том же файловом разделе. Не публиковать JSON раньше архива. Не изменять существующий ZIP под прежним именем. Проверить публичный HTTPS JSON и скачивание архива с отдельного Mac. Старые архивы удалять только после проверки обновления сотрудников; выключить предложение можно удалением JSON либо его заменой описанием текущей установленной сборки. Откат приложения на меньший номер сборки намеренно запрещён, исправление публикуется с новым номером.

## Защита установки

JSON ограничен 64 КиБ и 30 секундами, ZIP ограничен заявленным размером, пределом 2 ГБ и 10 минутами. Размер контролируется во время скачивания и после него. SHA-256 и точный размер проверяются до распаковки. Парсер ZIP проверяет центральные и локальные пути, отсутствие ссылок, дубликатов и выхода за AxisCopilot.app; ZIP64, шифрование, специальные файлы и распакованный размер свыше 4 ГБ отклоняются.

После распаковки проверяются совпадение номера/версии с JSON, идентификатор приложения, наличие arm64 и постоянная подпись того же сертификата, что у установленного приложения. Исходный помощник AxisUpdater повторно проверяет подготовленный комплект, ждёт выхода приложения, сохраняет предыдущую версию и выполняет замену с откатом при ошибке. Application Support не заменяется. Для обновления приложение должно находиться в /Applications либо ~/Applications и иметь доступ к записи в родительский каталог. Локальная подпись не заменяет Developer ID и нотариализацию для внешнего распространения.


## Кандидат 0.3.1 (11)

02.11.2026 сборка11 опубликована в alpha-канале. `latest.json` возвращает HTTPS200, архив имеет размер563856154 байта и SHA256 `f54c3236adc7762828ca7f79f834b7735e4a39f3f96d0c08826610aebc9d022d`. Перед атомарной публикацией JSON размер и хеш проверены на сервере. Установленное приложение11 успешно прочитало канал и показало последнюю совместимую версию. Полная приёмка обновления на втором Mac остаётся открытой. Подробные доказательства и ограничения находятся в `STATUS.md`; ниже сохранена процедура подготовки этого кандидата.

В исходном `Resources/Info.plist` уже выставлены версия `0.3.1` и сборка `11` для кандидата с новым интерфейсом и чатом. Это подготовка исходников, не подтверждение сборки, публикации, установки или проверки на втором Mac. Постоянные идентификатор приложения, сертификат подписи и адрес канала сохраняются.

Для этого кандидата номер повторно не увеличивать. После завершения правок интерфейса, проверок и ревью владелец выполняет:

```sh
timeout 1200 bash scripts/ci-local.sh
timeout 1200 bash scripts/package-employee.sh
python3 scripts/publish-update.py _output/employee-arm64/AxisCopilot.app \
  --output _output/update-channel \
  --feed-url https://updates.axisconsult.ru/copilot/alpha/latest.json
```

Упаковщик формирует комплект сотрудника и отдельный установочный ZIP. Из подписанного `employee-arm64/AxisCopilot.app` издатель формирует архив канала `AxisCopilot-11-arm64.zip` и `latest.json`. Каталог разработчика `_output/AxisCopilot.app` не публикуется. Серверный перенос и проверка обновления остаются отдельными шагами ниже; на втором Mac они пока не подтверждены.

## Номер релиза и проверяемый конвейер

Для следующего релиза одна команда выполняет увеличение версии, полный локальный прогон, сборку переносимого комплекта с whisper-cli, Small и моделями голосов, подпись, проверку подписей, подготовку ZIP и JSON:

```sh
bash scripts/publish-update.sh patch
```

Вместо patch выбрать minor либо major. Команда не меняет сервер и останавливается при любой ошибке. При ошибке проверки уже увеличенный исходный номер остаётся видимым в Resources/Info.plist; исправить ошибку и продолжить подробные шаги ниже без повторного увеличения либо осознанно выбрать следующий номер.

`CFBundleShortVersionString` использует major.minor.patch: patch для исправлений, minor для совместимой новой возможности, major для несовместимого изменения. `CFBundleVersion` увеличивается при каждом релизе независимо от изменения публичной версии. Смена номера выполняется в исходном Resources/Info.plist до сборки и подписи; подписанный bundle не редактировать.

```sh
python3 scripts/publish-update.py --bump patch
# Для другого масштаба релиза выбрать --bump minor либо --bump major.
timeout 900 bash scripts/ci-local.sh
timeout 1200 bash scripts/package-employee.sh
python3 scripts/publish-update.py _output/employee-arm64/AxisCopilot.app \
  --output _output/update-channel \
  --feed-url https://updates.axisconsult.ru/copilot/alpha/latest.json
```

Это подготовка артефактов. Затем выполнить серверный перенос архива и JSON в порядке, описанном выше, проверить HTTPS и контрольную сумму публичного архива, пройти обновление с предыдущей подписанной сборки и проверить разрешения. Не публиковать релиз по одному лишь успешному увеличению номера. Не отдавать сотрудникам закрытый ключ подписи. Исходники публичного репозитория и сервер официальных подписанных релизов являются отдельными каналами.

## Запросы Связки ключей при alpha-сборках

Постоянная подпись сохраняет проверяемую идентичность обновления, но self-signed сертификат не содержит Apple Team ID. macOS может привязать доступ Keychain к cdhash исполняемого файла и повторно потребовать подтверждение после пересборки. Сборка10 не подавляла диалог старого Keychain ACL. В сборке11 фоновые чтения дополнительно запрещают взаимодействие на время синхронного вызова и восстанавливают прежний режим; приложение показывает явную разблокировку в настройках вместо самопроизвольного запроса пароля. Секреты не удаляются и не переносятся. Полная постоянная авторизация между сборками требует Developer ID/Team ID и отдельной проверки, она не считается доказанной.

## Постоянное хранилище подключений 0.3.8 (18)

Один designated requirement недостаточен для login Keychain при самоподписанном сертификате без Team ID: partition ACL может хранить cdhash каждой сборки. Для новых подключений приложение устанавливает подписанный hardened-компонент AxisCredentials в закрытый Credentials/v1 каталога Application Support. Последующие обновления сохраняют этот файл побайтно, проверяя сертификат, идентификатор, SHA-256 и cdhash действующего процесса. Компонент принимает только два домена по наследуемым каналам, проверяет подпись и hardened runtime вызывающего приложения. Ключи остаются в login Keychain; открытых файлов с ключами нет.

Все операции компонента запрещают системные диалоги. Заблокированная Связка ключей возвращает ошибку; интерфейс не блокируется. При первом переносе старой записи выполняется тихое чтение; если macOS его отклоняет, можно повторно вставить вебхук в защищённое поле. Старый ключ не удаляется и права не сбрасываются. Миграция создаёт новую запись только при её отсутствии; параллельное сохранение или отключение имеет приоритет. Отключение создаёт защищённую отметку удаления, исключающую восстановление старого ключа.

Компонент v1 нельзя автоматически заменять при обновлениях приложения. Исправление самого компонента потребует отдельной версии протокола и проверенного переноса через прежний компонент. Локальная подпись не заменяет Developer ID и нотариализацию. Эта схема ограничивает доступ других приложений, но не обещает изоляцию от скомпрометированного пользовательского аккаунта.

Проверка: `bash scripts/check-credential-continuity.sh` использует только синтетические ключи в отдельном пространстве имён. Проверяет разные cdhash двух приложений, сохранение одного компонента, отказ постороннему приложению/повреждённому файлу, миграцию, гонки save/remove, повреждённую запись и предел размера.
