# Доступ MCP

Приложение предоставляет локальный сервер MCP через стандартные ввод и вывод. Запуск исполняемого файла установленного приложения с аргументом `--mcp` не открывает окно и не начинает запись. Сетевой порт не используется. Настройка конкретного клиента требует указать путь к исполняемому файлу, например `/Applications/AxisCopilot.app/Contents/MacOS/AxisCopilot`, и аргументы `["--mcp"]`. Пользовательские настройки клиентов приложение автоматически не меняет.

В интерфейсе «Доступ внешних агентов» требуется включить общий доступ и отдельно разрешить каждую выбранную встречу. Новые встречи закрыты. Список разрешений хранится в `mcp-access.json` в приватной папке записей (папка 0700, файл 0600). Сервер перечитывает разрешения при каждом вызове; отзыв действует и для уже подключённого клиента. Отсутствующий или повреждённый список закрывает доступ.

Если клиент MCP использует облачную модель, полученные тексты могут покинуть Mac. Локальный транспорт не делает облачного агента локальным. Это предупреждение отображается до включения доступа.

## Инструменты

1. `meeting_list` возвращает метаданные разрешённых встреч.
2. `meeting_search` ищет по названиям и транскрипции, возвращает фрагмент с исходным временем.
3. `meeting_get` возвращает метаданные и фактическое состояние манифеста без восстановления или изменения записи.
4. `meeting_transcript` возвращает фразы с ID, источником, временем начала и конца.
5. `meeting_summary` возвращает сохранённый локальный текст итогов.
6. `meeting_deal` возвращает локальный снимок CRM. Сеть и скачивание документов не используются.

`meeting_list` и `meeting_search` принимают необязательные `from`, `to`, `dealID`. Границы включают указанное время создания встречи. Даты задаются ISO8601 с временем, секундами и часовым поясом, например `2026-11-02T10:00:00+03:00`; доли секунды допустимы. Неверные даты, обратный диапазон и неверные типы параметров отклоняются. `dealID` является строкой с положительным десятичным ID до Int64.max без ведущих нулей. Совпадение проверяется только по сохранённому локальному снимку сделки явно разрешённой встречи. Отсутствующий, повреждённый или подменённый ссылкой снимок исключает встречу из результата фильтра по сделке. Запросов к CRM нет.

Сортировка списка и поиска: время создания по убыванию, при равном времени UUID по возрастанию. Смещения стабильны для неизменного архива и разрешений; добавление встреч или отзыв разрешения между страницами меняют набор результатов.

Все инструменты только читают. Нет начала записи, изменения CRM, доступа к произвольному пути, скачивания аудио или изменения разрешений. Аудио представлено количеством фрагментов и длительностью. Недоступный и неизвестный UUID имеют одинаковый ответ. Символические ссылки на папки или файлы встреч запрещены, как и ссылки вместо файла разрешений. Ответы не содержат путей к аудио и ключей.

Списки и транскрипция используют `offset` и `limit` (1–50), в ответе `nextOffset`. Итоги и CRM используют смещение и размер страницы в символах Unicode (1–16000). Пустой текст итогов означает, что сохранённого результата нет; сервер сам не запускает обработку. Текст встречи и снимок CRM считаются недоверенными данными, а не инструкциями для агента.

## Локальный журнал выдачи

В папке встреч сервер ведёт фиксированный `mcp-audit.jsonl` с правами 0600 и пределом 64 КиБ. При заполнении удаляются самые старые полные строки. Путь не принимается от клиента. Файл открывается относительно проверенной папки с запретом символических ссылок, проверяется как обычный файл текущего пользователя без жёстких ссылок; параллельная запись защищена блокировкой. При недоступном журнале сервер не выдаёт содержимое.

Строка содержит только время, имя известного инструмента, исход и количество. Для успешного чтения одной встречи добавляется её UUID; список и поиск сохраняют только количество выданных элементов. Для итогов и снимка сделки количество означает число выданных символов, для транскрипции число фраз. При отказе UUID отсутствует, количество равно нулю. Названия, тексты, поисковые запросы, фильтры, пути и ключи не записываются. Ошибка неизвестной и запрещённой встречи остаётся одинаковой. Журнал фиксирует подготовленную сервером выдачу, а не подтверждение получения клиентом.

## Протокол

Реализован MCP stdio с JSON-RPC 2.0: один JSON на строку UTF-8, `initialize`, `notifications/initialized`, `ping`, `tools/list`, `tools/call`. Поддерживаемые версии: `2025-11-25`, `2025-06-18`, `2025-03-26`, `2024-11-05`. До инициализации чтение инструментов запрещено. Уведомления не получают ответа. В stdout выводится только протокол.

Входной и выходной кадр ограничен 64 КиБ. Слишком большой ответ не обрезается: клиент получает ошибку с предложением уменьшить страницу. Это ограничение может потребовать меньший `limit` для необычно длинных фраз; исходная запись сохраняется целиком локально. Batch JSON-RPC, HTTP, серверные уведомления об изменении инструментов, sampling и удалённые roots не реализованы и не объявлены.

## Проверка

02.11.2026 синтетические проверки ядра подтвердили отдельное разрешение встречи, состояние `recording` без ложного восстановления, поиск с временем, немедленный отзыв, одинаковую ошибку неизвестной и закрытой встречи и запрет символьной ссылки на чужой манифест.

Полный обработчик JSON-RPC проверен на инициализации, уведомлении без ответа, списке шести инструментов, чтении текста с временем, неизвестных параметрах пути, отзыве доступа и ограничении кадра. Отдельно запущен настоящий stdio-подпроцесс с синтетическим хранилищем: initialize, tools/list, tools/call, живое состояние, изменение файла разрешений во время соединения и штатный EOF. Лишнего stdout и stderr не было.

Дополнительные синтетические проверки покрывают включённые границы времени, часовой пояс, неверные и нормализуемые даты, точный ID локальной сделки, одинаковое время создания и последовательность страниц, отсутствие снимка и ссылку вместо него. Проверки журнала подтверждают предел размера, права 0600, отсутствие текста/запроса и UUID отказанной встречи, запрет символической и жёсткой ссылки. Настоящий stdio-подпроцесс также проверяет фильтры, неверные типы и отказ выдачи при небезопасном журнале.

Подключение конкретного внешнего клиента к подписанному установленному приложению и его пользовательская настройка не проверялись этими тестами.

## Подключение из приложения

Откройте «Настройки», раздел «Доступ агентам», затем «Подключить клиент MCP». Кнопка «Скопировать JSON для агента» выдаёт конфигурацию клиентов с mcpServers. «Скопировать для Codex» выдаёт секцию config.toml. Используется фактический путь запущенного приложения, секретов в конфигурации нет. Общий доступ и разрешение выбранной встречи включаются отдельно. Публичный HTTP-сервер для этого не требуется.

Проверка `bash scripts/check-mcp.sh` включена в `scripts/ci-local.sh`. Выполненный 02.11.2026 тест настоящего подпроцесса подтвердил handshake, шесть инструментов, транскрипцию с временем, немедленный отзыв и EOF.
