# Axis Суфлёр

Дата: 02.11.2026. Статус: проектное описание для проверки и согласования.

## Назначение

Артём Саликов продаёт консалтинг Axis Consult. Во время встречи в Zoom или Яндекс Телемосте приложение на Mac слышит вопрос или возражение и автоматически предлагает короткий ответ, опираясь на отправленное клиенту КП и текущую сделку. Вопросы вводить не нужно. После встречи остаются аудиозапись, транскрипт с отметками времени, договорённости и доступ для агентов через MCP.

Подтверждённый контур проекта: Axis Consult; имя «Axis Суфлёр»; папка `project_sales-copilot`; тип code; приватный репозиторий `BlackWizlock/sales-copilot`. Каталог стандартов включён. Статья о результатах в общем vault появится после проверки прототипа.

Параметры продукта согласованы в переписке. Этот документ конкретизирует технический сценарий; предложения исполнителя выделены ниже и ещё не являются подтверждённым поведением программы.

## Что пользователь уже выбрал

1. Платформа Mac, запись микрофона и звука встречи.
2. Zoom и Яндекс Телемост как целевые приложения.
3. Русская транскрипция и автоматический суфлёр без ручного ввода вопросов.
4. Основание ответов: КП, отправленные материалы и поля текущей сделки Битрикс24.
5. Календарь Битрикс24.
6. Запуск из карточки сделки и фиксация разговора в сделке.
7. Локальная работа без подписки и платных API как основной режим.
8. OpenRouter как отдельно включаемая опция с выбором модели.
9. MCP для агентов с доступом к встречам из нашего приложения.
10. Сохранение реальной аудиозаписи. Granola можно оставить на переходное тестирование.

## Границы первого прототипа

Прототип состоит из последовательных проверяемых срезов; первый срез не объявляется выполнением всего проекта.

Срез A: нативное окно, разрешения macOS, запись двух источников и локальная русская транскрипция. Срез B: загрузка тестового КП, локальные автоматические подсказки. Срез C: чтение сделки, материалов и календаря Битрикс24, запуск из карточки. Срез D: MCP и OpenRouter. Срез E: запись встречи в CRM и проверка встроенного анализа Битрикс24.

Независимый участник-бот в Zoom/Телемосте, многопользовательское облако, мобильное приложение, публичный магазин приложений, миграция архива Granola и полноценная диаризация всех участников находятся за пределами первого прототипа. Для начала используем захват звука на Mac. Сроки и производительность не обещаем до замеров.

## Решения исполнителя для согласования

1. Нативное приложение Swift/SwiftUI, установленное локально. ScreenCaptureKit для звука приложения, AVFoundation для микрофона и сохранения. Минимальная целевая версия macOS 15, фактическая машина владельца macOS 27.0.1; совместимость зависимостей и SDK подтвердить сборкой.
2. WhisperKit является первым кандидатом локального распознавания. Конкретную версию и модель закрепить после проверки пакета. Голос каждого удалённого участника не обещаем: два источника «Я» и «Собеседники».
3. Для локальных подсказок первым кандидатом является движок семейства MLX. Выбор конкретной модели, лицензии и способа запуска остаётся исполнителю после короткого сравнительного теста на русском языке. Python-процесс допустим как локальный помощник, если Swift-вариант создаёт неоправданные препятствия; пользователь не должен запускать его вручную.
4. Хранилище SQLite с полнотекстовым поиском и локальные аудиофайлы в Application Support. Для короткого КП сначала поиск по тексту; векторную базу не вводить без необходимости.
5. MCP через отдельный локальный процесс со стандартным вводом/выводом. Общая БД открывается на чтение; приложение является единственным писателем. MCP не зависит от облачной модели.
6. Первый запуск из Битрикс24 допустим через явную ссылку открытия приложения. Полноценная вкладка карточки добавляется после проверки регистрации приложения, тарифов и безопасного возврата результата. Звук всегда захватывает приложение Mac.

## Сценарий встречи

До встречи пользователь выбирает сделку или открывает приложение из сделки. Приложение показывает название клиента, предложение, дату обновления контекста и список материалов. На этапе без подключения CRM загружается синтетический набор сделки. При ручном выборе другого клиента текущий контекст очищается, старые подсказки не переносятся.

КП выбирается из поля КП или явно загружается пользователем. Если предложение является презентацией, допускается выбор материала из документов сделки. Показываем, какой именно файл выбран; не считаем любой вложенный файл последней отправленной версией.

В прототипе обязательны PDF с текстовым слоем и TXT/Markdown. DOCX является следующим форматом при наличии простого локального извлечения. Сканированный PDF без распознанного текста показывает понятное ограничение; OCR не является скрытой облачной операцией. Пользователь видит извлечённый текст до встречи и может проверить суммы и сроки.

Пользователь выбирает источник системного звука Zoom, Телемост или браузер со встречей. Приложение запрашивает системные разрешения и показывает отдельные индикаторы уровня микрофона и собеседников. Для браузера предупреждаем, что другие звуки того же приложения тоже могут попасть в запись; выбор не равен гарантированной изоляции одной вкладки.

После «Начать встречу» отображаются время, состояние записи, два аудиоиндикатора, текущий текст и одна активная подсказка. Плавающее окно можно переместить; полноэкранный режим не обязателен. При демонстрации экрана пользователь сможет скрыть окно подсказок; невидимость для всех видов демонстрации не обещаем.

После «Завершить» файл закрывается, очередь распознавания дренируется, встреча получает итоговый статус. Пользователь может прослушать запись с отметки времени, прочитать текст и просмотреть краткое резюме и договорённости. Закрытие окна во время записи требует явного выбора: продолжить запись или завершить.

## Запись и восстановление

Микрофон и звук приложения сохраняются раздельно или как различимые каналы, с общей временной шкалой от начала сессии. Архивная смешанная копия M4A предназначена для воспроизведения и экспорта. Точный промежуточный контейнер и сведение остаются исполнителю; они не должны мешать восстановлению при аварии.

Запись закрывается небольшими сегментами, чтобы авария не уничтожала весь разговор. Предлагаемый интервал сегмента 30 секунд; предел возможной потери подтвердить тестом. На перезапуске незавершённая встреча помечается прерванной, доступные сегменты сохраняются и предлагается восстановление. Запись не возобновляется скрытно.

При потере источника, заполнении диска или отзыве разрешения состояние меняется явно. Нельзя показывать «Записываем обе стороны», когда доступна одна. Сбой модели не останавливает запись; сбой записи явно останавливает состояние успешного захвата. Смена устройства и Bluetooth проверяются отдельными сценариями.

Сохранять исходные каналы полезно для повторной транскрипции и поиска ошибок. Акустическое эхо при работе через динамики возможно; на первом тесте используем наушники. Качество с динамиками проверяем отдельно, подавление эха не считаем готовым по наличию библиотеки.

## Транскрипция и автоматические подсказки

Транскрипция работает инкрементально. Черновой текст можно исправлять; финальные сегменты имеют стабильный идентификатор, начало, конец, источник и версию. Суфлёр реагирует на законченные фрагменты, а не на каждую смену буквы. Очередь ограничена: при перегрузке запись продолжается, обработка догоняет с видимой задержкой.

Контекст подсказки включает недавний диалог, устойчивое резюме текущей встречи, факты сделки и найденные фрагменты выбранного КП. Файлы и речь рассматриваются как данные; инструкция внутри документа не может менять режим облака, права MCP или вызывать действия CRM.

Один локальный цикл оценивает, есть ли новый вопрос, возражение или момент для уточнения. Низкая полезность означает отсутствие новой подсказки. Одновременно не больше одного запроса генерации; новые события объединяются, устаревший ответ не заменяет актуальный. Предлагаемая защита от повторов: минимальный интервал 5 секунд плюс сравнение смысла; значение уточняется по тесту.

Карточка подсказки содержит максимум три короткие части: рекомендуемая реплика, уточняющий вопрос при необходимости и основание. Основание указывает файл/страницу или поле сделки. Если подтверждённой цены, скидки, срока или кейса нет, модель не придумывает его и предлагает уточнение. Числа, отображаемые как факты, должны иметь проверяемый источник. Это проверяется тестами, а не обещанием безошибочности модели.

Первичные цели для теста: видимый финальный фрагмент в пределах 5 секунд после конца реплики; подсказка в пределах 10 секунд. Это цели приёмки на данной машине после прогрева, не измеренные показатели. Если не достигнуты, отчёт содержит p50/p95 и выбранный компромисс модели/качества; критерий не меняется молча.

## Сделка и календарь Битрикс24

Канонический портал Axis Consult: axisconsult.bitrix24.ru. До обращения к живым данным проверить доступный канал и права. В текущей сессии инструмента bitrix24-axis нет; подключение не считать готовым. При разработке не читать ключи автоматически и не создавать новые CRM-поля.

Первое подключение получает сделку, схему доступных полей, связанные дела, документы и календарные события за выбранный период. Существенные поля: потребности клиента, предложение, сумма/валюта, договорённости, следующий шаг. Код поля берётся из проверенной схемы, а не угадывается по названию.

Календарь только читается. Событие связывается со сделкой по CRM-привязке, если она есть. При неоднозначности приложение просит выбрать сделку. Недавнее изменение даты в деле или событии важнее старого поля; расхождение показываем без перезаписи данных. Ссылки Zoom/Телемоста можно открыть пользователю, вступление в разговор остаётся обычным действием приложения встречи.

Приложение привязывает локальную сессию к числовому deal_id только после явного выбора. Ссылка открытия из браузера считается недоверенной подсказкой; сама по себе не даёт прав читать произвольный портал или начинать запись.

Для полноценной вкладки карточки требуется зарегистрированное приложение с публичным HTTPS-обработчиком и проверенной авторизацией. Возможность безопасного возврата в локальное приложение и соответствие выбранному тарифу проверяются до регистрации. Если понадобится собственный обработчик, это отдельный компонент с ограниченным содержимым, без передачи аудио или ключей модели через страницу.

## Сохранение разговора и вспомогательный анализ CRM

После завершения пользователь выбирает «Сохранить в сделку» и видит целевую сделку, длительность, запись, текст и резюме. Сохранение не начинается автоматически в действующей клиентской сделке во время разработки.

Базовый результат: дело встречи и доступная запись в выбранной сделке. Дополнительный результат: оформленный внешний звонок с записью, чтобы проверить штатную транскрипцию и анализ Битрикс24. Путь внешнего звонка требует OAuth-приложения и корректного полного жизненного цикла звонка; входящий webhook не считается достаточным. Номер участника не выдумывать: если телефон нужен методу, используется подтверждённый связанный контакт с предпросмотром либо сохраняется обычное дело встречи.

Внешний звонок нельзя регистрировать с неподдерживаемым CRM_ENTITY_TYPE=DEAL. Привязка CRM-дела к сделке выполняется поддерживаемым методом после изучения схемы, с повторным чтением. Конверсия записи в MP3/WAV для attachRecord делается локально, если метод не принимает исходный M4A. Не публикуем файл для скачивания, если поддерживается загрузка содержимого.

Повтор команды не создаёт дубль. Каждая сессия имеет устойчивый идентификатор; состояния регистрации, завершения, загрузки и привязки сохраняются. После сбоя операция продолжается с известного шага, а приложение перечитывает фактический результат.

Встроенный анализ зависит от тарифов, прав, допустимого формата, длины и размера записи, а также фактического триггера обработки. До теста на безопасной записи не утверждаем, что разбор стартует сам. Локальная запись, транскрипция и суфлёр работают независимо от этой функции. Поля сделки, сумма, стадия и даты не меняются без явного выбора владельца.

## MCP для агентов

MCP является интерфейсом к данным, а не системой распознавания. Нативный суфлёр работает автоматически без открытого чата агента.

Начальный набор инструментов только для чтения:

1. `list_meetings`: фильтр по периоду и разрешённой сделке, ограниченный список.
2. `search_meetings`: полнотекстовый поиск по разрешённым текстам с выдержками и отметками времени.
3. `get_meeting`: метаданные, состояние, краткий итог и ссылки на доступные ресурсы.
4. `get_transcript`: страницы финальных сегментов с курсором; для текущей встречи возвращается доступная часть с состоянием live.
5. `get_deal_context`: локальный снимок контекста выбранной встречи с датой загрузки, без произвольного проксирования REST.

Аудио доступно как локальная ссылка открытия в приложении; сырые байты не включать в ответы по умолчанию. Пути к файлам не принимать от клиента; meeting_id разрешается через БД, с проверкой разрешённого набора. Нет инструментов начала записи, удаления, изменения CRM или отправки сообщений.

Пользователь явно включает MCP и выбирает доступные встречи или сделки. По умолчанию нет доступа ко всему архиву. Экспорт фиксируется в локальном журнале без содержимого текста. Запрос к неразрешённой или удалённой встрече возвращает отказ без утечки метаданных. Пагинация и предел ответа обязательны.

Модель внешнего агента может быть облачной: текст, выданный MCP такому агенту, покидает Mac. Это отображается при включении доступа. Для полностью локального контура агент тоже должен использовать локальную модель. Конкретную интеграцию с клиентом агента проверить настоящим протокольным соединением, не только прямым вызовом обработчика.

## OpenRouter

Режим по умолчанию «Локально». Отдельно включаемый режим OpenRouter использует личный ключ из Keychain. Каталог моделей и цены получает из API; имя конкретной модели и провайдера фиксируются в настройках сессии. Наличие модели в каталоге не подтверждает доступность конкретному аккаунту.

Распознавание и архивирование остаются локальными. Для подсказки в облако передаётся текстовый пакет, но никогда исходное аудио. Для первого прототипа разрешён только синтетический или вручную обезличенный набор с явной отметкой пользователя; нельзя полагаться на автоматическое обезличивание как на доказанную защиту. Конфиденциальные клиентские документы, CRM-снимки и транскрипты заблокированы для этого режима.

Нужны потоковый ответ, отмена устаревшего запроса, таймаут, обработка 429/ошибок сети и явный локальный возврат. Возврат не отправляет данные другому облачному провайдеру. Строгий дневной предел реализуется консервативным резервированием максимальной стоимости запроса до отправки и сверкой фактического расхода; при неизвестной цене вызов не выполняется. Отображаем цену как оценку до подтверждения биллингом провайдера.

Модель для быстрого ответа и модель для итогового разбора могут различаться. Подписка на наше приложение не нужна, использование платных облачных моделей оплачивается отдельно. Никаких платных пробных вызовов до явного подключения пользователем ключа и бюджета.

## Локальные данные и удаление

Запись Meeting содержит UUID, дату начала/конца, статус, приложение-источник, deal_id при наличии, версию контекста и список материалов. TranscriptSegment содержит UUID, meeting_id, источник, время, текст и статус final. Suggestion содержит исходные сегменты, версию модели, текст и ссылки на основания. Document содержит локальный идентификатор, имя, хеш, версию и извлечённые страницы. CRMExport содержит удалённые идентификаторы и состояние повторяемой операции.

БД и записи хранятся в пользовательском Application Support с доступом только владельцу учётной записи. Системное шифрование диска зависит от настройки Mac; отдельное шифрование БД не обещается в прототипе. Пользователь может удалить встречу и её производные из локального хранилища, с учётом уже отправленных копий в CRM. Срок автоматического удаления в первом прототипе не устанавливается: хранение до ручного удаления, объём виден в интерфейсе. Удаление материалов и очистка полнотекстового индекса учитываются вместе.

Сеть в локальном режиме нужна только для первоначального получения моделей и явно включённых интеграций Битрикс24. Во время локального теста на синтетических данных запрет исходящего трафика не должен ломать запись, транскрипцию, поиск и суфлёр после установки моделей. Телеметрия и аналитика внешних сервисов не включаются.

## Проверка и приёмка

1. Установленное .app запускается на Mac владельца, запросы разрешений понятны. SDK на диске не заменяет этот тест.
2. Синтетическая встреча Zoom: оба участника различимы в аудио и тексте. Повтор для Телемоста. Используем наушники, затем отдельную проверку динамиков.
3. Stop закрывает запись; воспроизведение и переход по отметке времени работают. При аварии сохраняются завершённые сегменты; приложение не возобновляет запись само.
4. Замеры задержек после прогрева на 15-минутном разговоре: p50/p95 текста и подсказки, рост очереди, память и загрузка. Цели 5/10 секунд, указанные выше, проверяются отдельно.
5. Не менее десяти тестовых возражений по синтетическому КП: цена, срок, состав работ, сравнение, кейс и неизвестные условия. Не менее восьми уместных подсказок, ноль выдуманных числовых обязательств. Дубли и ошибочные срабатывания описываются.
6. Сравнительный запуск с Granola проверяет слышимость обеих сторон и нагрузку; параллельная работа заранее не гарантируется.
7. Подмена клиента очищает контекст. Скан без текста и неверный файл не дают ложной готовности КП.
8. Битрикс24: правильная сделка, календарь, дата контекста, отсутствие изменений при чтении. Ошибки доступа не ломают локальный сценарий.
9. Сохранение в тестовую сделку: запись доступна, повтор не создаёт дубль, при сбое можно продолжить. Факт штатного анализа проверяется в интерфейсе портала; если не запустился, функция остаётся неподтверждённой.
10. MCP: настоящий обмен initialize/tools/list/tools/call, пагинация, live-фрагменты и отказ неразрешённому meeting_id. Содержимое чужой встречи не утекает через поиск или ошибки.
11. OpenRouter: только синтетический набор, запрос без аудио, отмена/таймаут, дневной предел, отказ при отсутствии цены, отсутствие ключа в логах. Платный тест требует подключения пользователем.
12. Локальные функции продолжают работать без сети после загрузки моделей. Запись не зависит от работоспособности модели, MCP или CRM.

## Что пока не подтверждено

Совместимость конкретных моделей и их лицензий, сборка .app без полного Xcode, доступ к Битрикс24 и подписка портала, задержка русского распознавания, качество локального суфлёра, конкуренция с Granola, безопасный браузерный мост и автоматический запуск штатного анализа CRM. Это проверяемые задачи, а не основания считать функции уже готовыми.

## Уточнение интерфейса после просмотра VoiceInk и Granola

Источник: замечания владельца 02.11.2026 о перегруженном экране, множестве заголовков и неформатированном разборе; прямое поручение продолжать реализацию.

Основной экран содержит библиотеку встреч, одно название выбранной встречи, постоянную кнопку привязанной сделки и управление записью либо компактный плеер. Выбор сделки доступен до записи и для непривязанной сохранённой встречи. Кнопка открывает отдельный лист с поиском, карточкой привязки, календарём и предварительным просмотром отправки. Номер и название сделки остаются видны после закрытия листа.

Разбор читается как документ с компактными тематическими названиями и списками. Редактор включается отдельным действием. Отдельный чат отвечает по записи выбранной встречи с проверяемыми ссылками на реплики; история чата сохраняется локально вместе со встречей. Смена встречи очищает отображение прежнего чата и отменяет устаревший ответ. Клиентский текст не передаётся в OpenRouter.

Настройки используют боковую навигацию по коротким разделам: общие, распознавание, локальный ИИ, Битрикс24, OpenRouter, доступ агентам. Каталог моделей и технические параметры не занимают экран разбора. Участники открываются отдельной кнопкой. Плеер сохраняет паузу, переход по времени и выбор скорости; громкость открывается по кнопке.

Эти решения принадлежат реализации Codex на основе замечаний владельца. Факт наличия кода не заменяет визуальную приёмку, живую проверку личного подключения и сохранение в выбранной сделке.
